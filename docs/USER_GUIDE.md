# AI Dev Workbench 使用指南

## 平台简介

AI Dev Workbench 是一个 AI 驱动的开发工作台，将「需求获取 → 计划生成 → 代码执行 → 自动测试」串联为完整流水线，支持单任务和多任务并行开发模式。

核心能力：通过 Claude Code CLI 桥接 AI 引擎，在本地项目环境中完成从需求分析到代码交付的全流程。

---

## 功能模块

### 1. 需求管理 (Requirements)

**路径：** 首页 `/`

- 通过 MCP 协议从 ONES / Jira / GitLab 等第三方平台拉取需求
- 支持关键词搜索、需求详情查看
- 需求保存到本地后可在其他模块引用

**使用流程：**
1. 先在 MCP 页面配置好数据源连接
2. 进入需求页面，点击「获取需求」拉取远程数据
3. 选择需求 → 保存到本地需求库

---

### 2. 工作区管理 (Workspace)

**路径：** `/workspace`

- 添加本地项目目录作为工作区
- 浏览文件树、预览文件内容
- 查看 Git 状态（分支、变更文件列表、diff）
- Git 分支操作：切换、stash、merge、冲突查看
- 工作区收藏夹管理

**使用流程：**
1. 点击「添加工作区」选择项目目录
2. 系统自动检测项目类型（Node.js / Python / Java / Rust）
3. 点击工作区可浏览文件、查看 Git 状态

---

### 3. 流水线配置 (Pipelines)

**路径：** `/pipelines`

- 定义开发工作流模板（阶段名称、每个阶段的 AI 技能配置、测试策略）
- 设置项目默认流水线

**使用流程：**
1. 新建流水线，定义 Plan / Execution / Test 各阶段参数
2. 在工作区或创建任务时选择对应流水线

---

### 4. AI 计划生成 (Plan)

**路径：** `/plan`

**单任务模式核心步骤之一。** 基于选定的需求和项目上下文，AI 生成结构化开发计划。

- 选择工作区 + 需求 → AI 自动分析项目代码 → 生成开发计划
- 支持多轮对话：对计划不满意可直接回复补充要求
- 计划内容包含：任务拆分、文件修改清单、实现步骤

**使用流程：**
1. 选择工作区和需求
2. 选择流水线配置
3. 点击「生成计划」
4. 查看计划内容，可通过回复框补充/修改要求
5. 确认计划后进入执行阶段

---

### 5. AI 代码执行 (Execution)

**路径：** `/execution`

**单任务模式核心步骤之二。** AI 按照开发计划逐步执行编码任务。

- 逐步执行计划中的每个步骤
- 实时显示 AI 输出和代码变更
- 支持暂停、重试、跳过、中止
- 执行完成后可运行测试验证

**使用流程：**
1. 计划生成确认后自动进入执行（或从计划页手动触发）
2. 实时查看 AI 操作日志
3. 随时暂停/中止，可回复补充指令
4. 执行完成后查看变更

---

### 6. 自动化测试 (Tests)

**路径：** `/tests`

- 自动检测项目使用的测试框架（Jest / Pytest / Maven 等）
- 运行现有测试或让 AI 生成测试
- 查看测试结果和历史记录

---

### 7. 项目空间 (Projects) — 多任务并行

**路径：** `/projects`

**多任务并行开发的核心入口。** 在同一项目（工作区）下创建多个开发任务，通过看板式界面管理和监控。

#### 核心特性

| 特性 | 说明 |
|------|------|
| 看板管理 | 运行中 / 排队中 / 等待依赖 / 已完成 四列看板 |
| 依赖编排 | 任务间设置前置依赖，前置全部完成后自动启动 |
| 分支隔离 | 每个任务自动创建 `task/{name}-{id}` 分支，基于用户选择的基础分支 |
| 阶段确认 | Plan 生成后暂停等确认 → 执行完成后暂停等确认，用户全程可控 |
| Stash 保存 | 任务完成后代码按 `req-{需求号}` stash，不自动合并 |
| 实时日志 | WebSocket 推送任务日志，实时查看 AI 操作 |

#### 使用流程

```
创建任务 → 启动 → [AI生成计划] → 确认计划 → [AI执行] → 确认完成 → stash保存
```

**详细步骤：**

1. **选择工作区** — 左侧列表点击已收藏的工作区
2. **新建任务** — 点击「新建任务」按钮
3. **配置任务：**
   - 选择需求（从需求库中选取）
   - 选择流水线配置
   - 选择基础分支（下拉拉取远程分支列表）
   - 可选：勾选前置任务（设置依赖关系）
4. **启动任务** — 点击「创建并启动」
5. **查看计划** — AI 生成计划后自动暂停，看板卡片显示「等待确认计划」
6. **点击任务卡片** → 右侧详情面板查看日志和计划内容
7. **确认计划** — 点击「确认计划，开始执行」，AI 开始编码
8. **确认执行** — 执行完成后再次暂停，点击「确认执行完成」
9. **完成** — 代码自动 stash，可随时通过 `git stash list` 找回

#### 任务控制

| 操作 | 说明 |
|------|------|
| 确认 | 推进任务到下一阶段（计划→执行→测试） |
| 暂停 | 暂停当前执行 |
| 恢复 | 恢复暂停的任务 |
| 终止 | 强制终止任务 |
| 删除 | 删除任务并清理分支 |
| 回复 | 向 AI 发送补充指令 |

---

### 8. MCP 服务器 (MCP)

**路径：** `/mcp`

- 管理 MCP Server 连接配置
- 测试连接是否可用
- 配置的数据源可供需求模块拉取数据

---

### 9. 技能管理 (Skills)

**路径：** `/skills`

- 查看、创建、编辑、删除 Claude Code 的技能文件（`.claude/commands/`）
- 技能可在流水线中引用，定制 AI 行为

---

### 10. 文档解析 (MinerU)

**路径：** `/mineru`

- 上传文档（PDF / Word / 图片），通过 MinerU 引擎解析为结构化文本
- 支持异步解析任务，查看解析结果

## 典型工作流

### 单任务流程（Plan → Execution）

```
需求管理 → 选择需求
    ↓
Plan 页面 → 选择工作区 + 需求 → 生成计划 → 多轮修改 → 确认
    ↓
Execution 页面 → AI 逐步执行 → 实时查看 → 暂停/补充 → 完成
    ↓
Tests 页面 → 运行测试 → 验证结果
```

### 多任务并行流程（Projects）

```
项目空间 → 选择工作区 → 新建多个任务（可设依赖关系）
    ↓
任务1: 计划 → 确认 → 执行 → 确认 → stash
任务2: 等待任务1完成 → 自动启动 → 同上流程
任务3: 独立运行 → 同上流程
```

## 数据存储位置

所有配置和数据文件存储在 `~/.ai-dev-workbench/` 目录下：

| 文件 | 内容 |
|------|------|
| `config.json` | 全局配置 |
| `saved-workspaces.json` | 工作区收藏列表 |
| `workspace-history.json` | 工作区访问历史 |
| `mcp-servers.json` | MCP 服务器配置 |
| `pipelines.json` | 流水线定义 |
| `skills/` | 技能文件目录 |
| `requirements/` | 需求数据（按需求 ID 分文件夹） |
| `tasks/` | 任务持久化数据 |

---

## 环境要求

- **Node.js** >= 18
- **Claude Code CLI** 已安装并配置（AI 能力的基础）
- **Git** 已安装（分支管理和版本控制）
- **网络** 本地开发模式无需公网，AI 调用需要 Claude API 访问权限
