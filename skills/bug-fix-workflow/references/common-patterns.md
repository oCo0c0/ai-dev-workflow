# 常见 Bug 模式参考

> 根因分析阶段的辅助参考，按类型分类的常见 Bug 模式和排查思路。

---

## 一、空指针 / NullPointerException

### 常见原因
- 链式调用中间对象为 null（`a.getB().getC()`）
- 集合/数组未初始化
- Map.get() 返回 null 后直接使用
- 数据库查询结果为空未处理
- 配置项缺失返回 null

### 排查思路
```
1. 查看堆栈中的行号，定位哪个对象为 null
2. 向上追溯该对象的来源（参数传递、方法返回值、字段赋值）
3. 确认是否缺少 null 检查，或应在源头避免 null
```

### 修复模式
```
- Optional 链式调用：Optional.ofNullable(obj).map(Xxx::getYyy).orElse(default)
- 前置校验：if (obj == null) return / throw
- 空对象模式：返回空集合而非 null（Collections.emptyList()）
- Hutool/ObjectUtil 工具方法
```

## 二、类型转换错误 / ClassCastException

### 常见原因
- 泛型擦除后强转失败
- JSON 反序列化类型不匹配（Integer vs Long, List vs Map）
- 接口多个实现类之间强转
- 基本类型与包装类混用

### 排查思路
```
1. 确认实际类型和目标类型
2. 追溯数据来源（序列化/反序列化、集合存入时的类型）
3. 检查是否存在泛型信息丢失
```

---

## 三、并发问题

### 常见原因
- 共享可变状态未同步
- HashMap 并发修改（ConcurrentModificationException）
- 检查-执行竞态（check-then-act）
- 连接池/资源池耗尽

### 排查思路
```
1. 确认问题是否间歇性出现
2. 检查共享变量是否加锁或使用线程安全容器
3. 查看是否有 @Async、@Scheduled、CompletableFuture 等异步代码
4. 检查数据库事务隔离级别
```

### 修复模式
```
- ConcurrentHashMap 替代 HashMap
- Atomic 变量替代基本类型
- 同步块（注意粒度和顺序，避免死锁）
- ThreadLocal 隔离线程数据
```

## 四、数据库相关问题

### 常见原因
- SQL 语法错误
- 字段类型/长度不匹配
- 事务边界不正确（@Transactional 配置）
- N+1 查询性能问题
- 死锁

### 排查思路
```
1. 查看完整 SQL 日志（开启 MyBatis SQL 日志）
2. 在数据库客户端直接执行 SQL 验证
3. 检查事务注解是否生效（同类方法调用不走代理）
4. 检查索引是否命中（EXPLAIN 执行计划）
```

## 五、内存泄漏 / OOM

### 常见原因
- 集合持续增长未清理
- 缓存无过期策略
- 大量创建线程/连接未关闭
- 静态集合持有对象引用

### 排查思路
```
1. 使用 jmap/jstack 查看堆内存和线程状态
2. 关注集合类型的字段是否有清理机制
3. 检查是否有资源未 try-with-resources 关闭
4. 检查 ThreadLocal 是否 remove
```

## 六、配置 / 环境问题

### 常见原因
- 配置项在不同环境值不同
- 配置中心配置覆盖本地配置
- 端口冲突 / 依赖服务不可用
- 时区差异（服务器时区 vs 数据库时区）

### 排查思路
```
1. 对比不同环境的配置文件
2. 检查 Nacos/Apollo 等配置中心的有效配置
3. 确认依赖服务的健康状态
4. 打印实际生效的配置值（@Value 注入后 log 输出）
```

---

## 七、接口集成问题

### 常见原因
- 第三方接口参数/返回值变更
- 超时设置不合理
- 重试策略不正确（非幂等接口重试导致重复）
- 编码/序列化不匹配（UTF-8 vs GBK，JSON vs XML）
- 证书/鉴权过期

### 排查思路
```
1. 抓取实际请求和响应（日志/抓包工具）
2. 与接口文档逐字段对比
3. 检查超时配置（连接超时 vs 读取超时）
4. 确认鉴权信息是否有效
```

---

## 八、前端交互问题

### 常见原因
- 前后端数据格式不一致（日期格式、数字精度）
- CORS 跨域限制
- 请求参数绑定失败（字段名不匹配）
- 响应序列化问题（循环引用、LazyInitializationException）

### 排查思路
```
1. 查看浏览器 Network 面板的实际请求/响应
2. 对比前端发送的参数名和后端接收的字段名
3. 检查后端返回的 JSON 结构是否与前端期望一致
4. 查看后端日志是否有参数绑定错误
```

## 快速诊断检查清单

当遇到 Bug 时，快速过一遍以下清单：

```
□ 查看完整错误堆栈，不要只看第一行
□ 检查最近一次代码变更（git log / git diff）
□ 确认环境是否一致（配置、数据、依赖版本）
□ 检查日志上下文（错误前后的日志）
□ 复现时使用与报告者相同的数据和操作
□ 搜索项目内是否有同类问题的历史修复
□ 搜索 Issue/工单系统中是否有相关记录
```
